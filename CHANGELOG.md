# Changelog

All notable changes to this project are documented here.

## [Unreleased]

### Added
- `->toResource()` / `->toResourceCollection()` responses now resolve their receiver from any statically-declared type, not only a Model-typed parameter: a Model-typed property, a method whose declared return is a concrete Model, a base-`Model`/`self` passthrough call (typed from its Model argument, e.g. `$request->resolve($model)`), a local assigned from `new Model()` / a model-returning static factory (`Model::create()`/`findOrFail()`/…), and a local narrowed by `assert($x instanceof Model)`. (#540)
- A `->toResource()` passthrough receiver also resolves when the callee declares an identity `@return T` generic (`@template T of Model` / `@param T $x` / `@return T`), regardless of how many branches its body has — the declared generic return type alone ties the result to the argument. Un-annotated methods still require the single-return body proof. (#543)
- A `->toResource()` property receiver resolves its model from a class-level `@property`/`@property-read` PHPDoc tag (walking parents) when there is no native typed property — the conventional way Eloquent relations and accessors declare their type. (#545)
- A no-argument `->toResourceCollection()` resolves the collection element from a `Collection<…, Model>` generic on the receiver — a `@property` collection relation (`$model->comments`) or a method's `@return C<Model>` (`$repository->recent()`) — emitting a collection of that model's resource. An untyped receiver (e.g. a query-builder `->get()` local) still refuses. (#547)
- Laravel 13's first-party `JsonApiResource` is documented as a JSON:API resource object (`type`/`id`/`attributes`/`relationships`/`links`/`meta`), reading each member from its `to*()` literal with the same bounded rule as `toArray()`. Previously every such resource produced an empty schema. (#536)
- `openapi:generate` no longer aborts when swagger-php emits a validation warning. The warnings are collected and reported; the run fails only on `validate()`'s own verdict. Previously a host error handler that promotes `E_USER_WARNING` to an exception (Laravel's does) turned any warning into a fatal, so a legal document with a float `multipleOf` — as inferred from a `decimal` column — crashed the very first run with no file written. (#539)
- `AstLiteralEvaluator` resolves `self::`/`static::` class constants when the caller supplies the enclosing class, so array literals keyed by class constants are no longer refused wholesale. (#538)
- `WrappedModelLocator` reads `@template-extends` alongside `@extends` when locating the wrapped model.
- **Tier-1 controller body inference**: request bodies from inline `validate()`, error responses from `abort()`/`abort_if()`/`abort_unless()`, primary responses from literal `response()->json()`, API Resource shapes from `toArray()`, Fractal `transform()` literals, and `spatie/laravel-query-builder` fluent chains; query parameters from `$request->*()` accessor reads, and inline `validate()` keys on GET/HEAD routes as query parameters. (#9, #10, #12, #13, #14, #15, #16)
- **SwaggerPhp plugin** harvests hand-authored `#[OA\*]` / `@OA` annotations into the spec, with `migration.*` lint rules and `--fix` to delete annotations inference already covers. (#17, #122, #196)
- Response schemas inferred from Eloquent model metadata (`$casts`, `$hidden`, `$appends`, migration columns, framework timestamps) and from concrete API Resources resolved off the controller's return expression. (#18, #108, #250)
- A backed enum referenced anywhere emits a single reusable component `$ref`'d at every site. (#35)
- Array-shape PHPDoc (`array{foo: string}`) resolves to an object schema instead of a bare `array`. (#127)
- Discriminated request bodies via `#[RequestBody(discriminator: …)]` + repeatable `#[RequestVariant]` (OpenAPI `oneOf` + `discriminator`).
- New authoring attributes/options: `#[SchemaName]` (pins the component key), `#[RequestField]` on actions, `#[Summary]`/`#[Description]`, `#[Deprecated]` (and `@deprecated` PHPDoc), `#[Expose]`, `#[Security]` (repeatable), `#[ResponseHeader]`, `#[ResponseField]`/`#[ResourceField]` enum and nested-collection support, and `#[Tag]`/field `enum:` accepting backed enums. (#38, #110, #126, #128, #205)
- Richer Tier-0 inference: route-model-bound and enum-backed path parameters typed from the model key / backed enum, custom-key bindings (`{post:slug}`), nested/wildcard validation keys, `mimes:`/`mimetypes:` file uploads, `Route::any()` verb fan-out, and conventional success status + summary for resourceful actions.
- Security inference: Sanctum auto-derivation, `abilities:`/`ability:` middleware scopes, `openapi.security_schemes`, `openapi.security_default_scheme`, and `openapi.security_middleware_map` config keys.
- `SelfDocumentingRule` interface lets custom validation rules contribute schema constraints (description, type, format, pattern, example).
- Faker-backed example synthesis for FormRequest and Spatie Data fields, with `@example` / `@no-example` / `@enum` inline directives.
- Multi-spec support: `config('openapi.specs')` emits multiple documents; per-spec `info` overrides deep-merge.
- `openapi.error_envelope` config key with `none` / `laravel` / `rfc7807` / `json-api` presets for standard error response bodies.
- `openapi.overrides` config escape hatch for operation-level fields, with `overrides.unknown-field` / `overrides.unused` lint rules.
- Served docs playground can render with Swagger UI as an alternative to Scalar.
- Bundled PHPStan extension catches attribute misuse at edit time, before generation.
- Lint coverage: `openapi:lint` reports a documentation-coverage metric and gates CI via `--min-coverage` / `--max-findings`; repeatable, target-addressable `--format=<format>[:<target>]` with a new `lcov` format; `--fix`/`--check` auto-fix; sharper route-scoping flags (`--uri`, `--diff`). New rules include `query-builder.filter-duplicate`, `resource.response-empty`, `operation.return-type-missing`, `response.success-empty-body`, `request-body.schema-degraded`, `response.ref-unresolvable`, and the visibility/fractal families.
- `SpecStage`, `ErrorResponseContributor`, and `ResourceTargetLocator` plugin extension points; observability events for generation and linting.
- Default route filters for first-party operational packages (Horizon, Pulse, Nova, Telescope, Ignition, Passport, and the library's own routes via `SkipSelfRoutes`).
- `openapi:diff:config` command reporting drift between the published config and the package default.
- String-keyed array/collection properties on Spatie `Data` classes (`array<string, T>`) emit `additionalProperties` (a map) instead of a bare array. (#334)
- `#[CookieParam]` authoring attribute documenting an `in: cookie` parameter read off the request at runtime. (#335)
- `x:` vendor-extension passthrough on the field attributes (`#[ResponseField]`, `#[RequestField]`, `#[QueryParam]`, `#[PathParam]`, `#[CookieParam]`): attach `x-*` specification extensions to a field's schema, co-located with the field (the field-level analogue of `openapi.overrides`). (#336)
- `additionalProperties:` override on the field attributes (`#[ResponseField]`, `#[RequestField]`, `#[QueryParam]`, `#[PathParam]`): set a field's map behaviour to a bool or a typed value schema; applied last, it wins over inferred `array<string, T>` map values. (#345)
- `#[RawSchema]` class-level attribute replaces a payload class's inferred component body with a literal JSON Schema (Spatie Data, API Resource, FormRequest); keywords are bounded to what swagger-php serialises, with unsupported keywords dropped-and-logged and flagged by the new `schema.raw-keyword-unsupported` lint rule. (#344)
- Pagination query parameters from a `->paginate()`/`->simplePaginate()`/`->cursorPaginate()` body call (Tier-1): offset paginators emit `page`/`per_page`, cursor paginators emit `cursor`; an explicit `#[QueryParam]` wins for its name. (#31)
- Success-response model schema inferred from a directly-returned `Model::find()`/`findOrFail()`/`firstOrFail()` call in the controller body (Tier-1), feeding the existing Eloquent model→schema reader; composes with the `findOrFail()` 404. (#97)
- Fractal responses inferred from the `fractal()` helper, the `Spatie\Fractalistic\Fractal` facade, and injected-`Manager` `new Item`/`new Collection` resource construction (Tier-1 body scan), with `item`/`collection` envelopes and `serializeWith(...)` serializer detection; the bare two-argument `fractal($data, new T())` form, a variable transformer, and an unrecognised serializer all degrade with a note, and `#[FractalResponse]` remains authoritative. (#263)
- `schema.class-attribute-conflicts-with-field-attributes` lint rule (advisory): flags a payload/return class carrying a class-level `#[RawSchema]` alongside property-level field attributes (`#[RequestField]`/`#[ResponseField]`), which the raw schema replaces wholesale, leaving the field attributes dead. (#351)
- Regression guard: `#[RawSchema]` documents using the nested-schema keywords `additionalProperties` (as a schema), `patternProperties`, `propertyNames`, `contains`, and `discriminator` produce a document that passes swagger-php's `validate()` (the raw-array-under-a-schema-keyword shape is accepted on both supported majors, 5.8 and 6.x), with the serialised shape pinned by per-keyword assertions. No conversion is needed. (#352)
- `#[ResponseExampleFile('path.json')]` authoring attribute attaches a JSON file's contents as the singular `example` on a response (the auto-derived primary by default, `status:` targets a declared response). Skipped silently for a conventionally bodyless status (204/205/304) or a status with no matching response, and yields to named `#[ResponseExample]`s already on the same media type (`example`/`examples` are mutually exclusive). (#40)
- `openapi:lint --format=markdown` now renders a real GitHub-Flavored Markdown body (a coverage summary line and a `Severity | Rule | Location | Message` findings table) instead of aliasing the CLI tree dump, so the CI coverage-comment recipe can post it verbatim. (#389)
- ApiResources: the return-expression reader now recognises the `X::collect(...)` static resource-collection factory, emitting the same collection response schema as `X::collection(...)`. (#390)
- `openapi:lint --fix` now repairs missing and codegen-unsafe operationIds (synthesizes/sanitizes the `#[Operation(operationId: …)]`), via the new `AddAttribute` fix primitive. (#382)
- `--fix`/`--check` now detect same-node fix conflicts (apply the safe subset, skip + report the rest with a typed reason) and emit a frozen `--check --format=json` fix-run envelope for CI. (#22)
- `--fix`/`--check` now take an optional `safe|dangerous` level; destructive fixes are withheld from the default `--fix`, counted (`withheld_destructive` in the JSON envelope), and gated behind `--fix=dangerous` plus a clean working tree (`--allow-dirty` overrides). (#383)
- `migration.oa-replaceable-by-attribute` lint rule + fixer (SwaggerPhp plugin, `migration.*` family, level 4): rewrites a hand-authored `#[OA\Property]` on a Spatie Data property as `#[ResponseField]` and a query `#[OA\Parameter]` as `#[QueryParam]`. The rewrite reproduces (bidirectional `SchemaEquivalence`) exactly what the annotation declared, so the generated document is unchanged or improved, never degraded. Phase 1 fires only when every carried key is a scalar attribute argument; non-scalar shapes (`enum`, array `example`, `x`, union `type`) are logged and left in place. (#195)
- The SwaggerPhp harvester now picks up reusable `@OA\Response(response: 'X')` / `@OA\Parameter(parameter: 'Y')` component definitions, emitting them under their authored names in `components.responses` / `components.parameters` and pulling in any schema they reference transitively. An operation `$ref` to a harvested component keeps its `$ref` (previously dropped + logged); a `$ref` to a genuinely-absent component is still dropped and logged, never emitted as a dangling `$ref`. (#201)
- `migration.oa-redundant-component-with-inference` lint rule + fixer (SwaggerPhp plugin, `migration.*` family, level 4): flags (and `--fix` removes) a reusable `@OA\Response` / `@OA\Parameter` component definition the generator already reproduces inline via inference. The oracle is usage-site (a component is redundant only when at least one operation `$ref`s it and every such operation's inference-only counterpart subsumes what the component contributes), with a dangling-`$ref` guard that keeps a component another surviving annotation — a schema, an operation, or a transitive component alias — still references. `--fix` removes only the targeted block, leaving sibling component definitions on the same class untouched. (#202)
- `migration.oa-redundant-property-with-inference` lint rule + fixer (SwaggerPhp plugin, `migration.*` family, level 4): the per-member counterpart of the whole-class redundancy rule. Flags (and `--fix` removes) an individual member `#[OA\Property]` / `@OA\Property` on a Spatie Data class inference already subsumes, leaving the enclosing schema and its load-bearing siblings (a member carrying a human `description`, an `enum`, a constraint) byte-identical. Scoped to Spatie Data members, whose component is emitted by inference and named by the PHP class, so removing a subsumed member annotation provably cannot change the emitted schema; API-Resource / request-DTO member `OA\Property` (inside a harvester-emitted class-level `#[OA\Schema]`) is correctly out of scope. (#197)
- Survey harness: `tools/survey/synthesize.php` reads the Layer A aggregate (`results.json` + `manifest.json`) and per-app Layer B1 `lift.json` files and emits two report **candidates** into the survey workspace — a public field-report candidate (no published-spec/competitor numbers, app-name publication gate per #159) and an internal synthesis candidate (coverage, recurring-gap rollup, per-app annotation-lift breakdown) — each carrying a provenance manifest. Deterministic: the same inputs reproduce the same structure. Candidates are for maintainer review only; nothing is auto-committed. (#176)
- ApiResources: an API Resource `toArray()` field reading a wrapped **non-Model value object**'s statically-typed public properties is now typed from those property types — both `$this->wrapped->field` (the wrapped object declared as a typed property on the resource) and `$this->field` (a non-Model class named by `@mixin`/`@extends`). The Model path is tried first (no regression); untyped, union-typed, or otherwise unmodellable source properties stay unconstrained (never-wrong). (#411)
- `#[RequestBody]` and `#[Response]` accept a `mediaTypes` list to offer the same body/response under multiple content types (e.g. `application/json` + `application/yaml`), emitting one media-type entry per declared type carrying the same schema. The single-`mediaType` behaviour is unchanged; `mediaTypes` wins over `mediaType` when both are set. (#410)
- An action method's `@param $name <description>` PHPDoc text supplies the description for the matching path or query parameter, as a lowest-precedence fallback (an authoring `#[PathParam]`/`#[QueryParam]` description and an inline-`validate()` trailing comment still win; the `@param` *type* is not used). (#418)
- Fractal response inference now recognises the `spatie/laravel-fractal` `$this->fractal` builder property as a chain root, and reads the transformer from a separate literal `->transformWith(new T()|T::class)` link when `item()`/`collection()` carries no second-argument transformer. A variable/dynamic `transformWith(...)` still degrades with a note. (#427)
- Eloquent model response fields are enriched from `database/migrations/*.php` (Tier-1 bounded AST over `Schema::create()`/`table()` `Blueprint` chains, keyed by table): column `format` (uuid/ip/date/date-time), mac-address `pattern`, `maxLength`, unsigned `minimum`, decimal `multipleOf`, `enum`/`set` members, `nullable`, literal `default`, and `comment`→`description`. These rank below `$casts`/`@property`/attributes (they fill only undefined fields) and degrade silently on dynamic table/column names, `->change()` alter chains, off-whitelist macros, and unparseable files. Opt out with `openapi.read_migration_columns`. (#414)
- Eloquent model response `default` is filled from the model's static `$attributes` array (Tier-0 reflection via `getAttributes()`), ranking below `$casts`/`@property`/attributes and below a migration `->default()`; an explicit `null` entry is honoured as `default: null` and a `$ref` property takes no `default`. (#439)
- API Resource `toArray()` (and Fractal `transform()`) whose body assigns the array to a variable and returns it (`$data = [...]; return $data;`) is now read like the inline-literal form, when the variable is assigned that literal exactly once on the unconditional path; a *conditional* later augmentation (`if (…) { $data += [...]; }`) leaves the base literal as a never-wrong subset, while an *unconditional* extra write (`$data['k'] = …` or `$data += [...]`) refuses, falling back to the wrapped model schema so always-present fields are never dropped. `$this->unless(…)` is recognized as the optional-field inverse of `$this->when(…)`. (#446)
- FormRequest request bodies fall back to a static read of the `rules()` array literal (a bare `return [ … ];` or a `$rules = [ … ]; … return $rules;` variable return, via a Tier-1 bounded AST scan) when invoking `rules()` throws on runtime state; conditional `$rules[…] = …` tweaks are ignored and a genuinely dynamic `rules()` still degrades with a log note. (#449)
- `routes.playground.spec_url` config key (env: `OPENAPI_PLAYGROUND_SPEC_URL`): when set to a non-blank value, the playground passes this URL verbatim to the renderer instead of the auto-derived spec route URL. Useful when `TrustProxies` middleware cannot be used (CDN-hosted specs, stripped proxy headers). A blank value is treated as unset. (#441)
- A base-resource (`JsonResource` / `AnonymousResourceCollection` / `ResourceCollection`) action whose body has several top-level `return` statements now infers the response when every branch resolves to the **same** resource (class, cardinality, and pagination all agreeing); bare `return;` and `return null;` guard clauses are ignored. Divergent or unresolvable branches keep degrading with a generation-log note, so a wrong response is never emitted. (#451)
- A generic-container return type that carries no item type — `Illuminate\Support\Collection`, Eloquent `Collection`, `LazyCollection`, or builtin `array` — now resolves its response schema from the return-expression body factory: API Resources via the existing `X::collection(…)` / `X::collect(…)` / `X::make(…)` / `new X(…)` scan, and Spatie Data via a new minimal `DataClass::collect(…)` / `new DataClass(…)` reader. Paginators stay with the paginator response resolver; an unrecognised body degrades silently. (#447)
- Survey harness: `tools/survey/typedness.php` segments an app's API operations by action-return shape (typed payload / correctly-empty / dynamic) and reports unaided substantive coverage *conditioned* on that shape — the well-typed coverage bar. `corpus.json` carries a per-app `typedness` tier; `--corpus` rolls up by tier. Methodology, segmentation criteria, and the recommended-bar proposal live in `tools/survey/well-typed-bar.md`. (#460)
- API Resource responses are now inferred for actions that declare a loose response wrapper return type (`JsonResponse`, `Response`, and their Symfony parents) while returning a standard resource construction (`UserResource::make(…)` / `::collection(…)` / `new UserResource(…)`) — the return-expression body scan is now consulted for these types, where before it was skipped and no schema was emitted. Retires most `#[ResponseResource]` uses on the loose-return idiom; the attribute stays the escape hatch for genuinely loose runtime shapes. (#487)
- Cookie and header parameters are now inferred from `$request->cookie('…')` / `$request->header('…')` reads in the controller body (Tier-1 bounded scan, the same whitelist that already reads `$request->query()`), emitted as optional `string` `in: cookie` / `in: header` parameters on every verb. Names are kept as literal tokens (no dotted→bracket transform). `#[CookieParam]` / `#[Header]` attributes fold in last and win over an inferred read of the same name, symmetric to the `#[QueryParam]` lock; a non-literal name degrades with a generation-log note naming the matching attribute. (#488)
- `routes.playground.auth.persist` and `routes.playground.auth.preferred_scheme` config keys wire bearer/token "Authorize" into both the Scalar and Swagger UI playground shells (#120).
- Baseline typed-return response schemas: a controller that types its return as a plain DTO, a documented `@return array{…}`, a scalar, a backed enum, a string-keyed map, or a typed collection of those now gets a response schema at the language level, without any convention package. A plain DTO's schema is built from its public and constructor-promoted typed properties (nested DTOs become their own pooled `$ref`, cycle-safe); anything that cannot be typed without guessing (untyped/`mixed`/`void`, a service object with no usable properties, a collection/resource wrapper, or a class carrying an authored `#[OA\Schema]`) degrades to the bare `200 OK`. The resolver runs after every convention plugin, so Spatie Data, Eloquent, API Resource, Fractal, and paginator returns keep their existing schemas; it fires only when they all decline, and works with the Core plugin disabled. (#479)
- Primary responses are now also read from a `new JsonResponse([...], status)` construction (imported or fully-qualified `\Illuminate\Http\JsonResponse`, app subclasses included), at parity with `response()->json([...])`: same Tier-1 bounded scan, body/status from positional or named (`data:`/`status:`) arguments, `204`/`HTTP_NO_CONTENT` body-less, an explicit status deferring the resource convention, and a non-literal status degrading with a note. (#453)
- An action that returns a **same-class response helper** directly (`return $this->empty();`, the helper declared on the controller or an ancestor/trait) is read one hop for the status it documents, emitting a contentless `204`/`205` where the helper builds a body-less response (`response()->noContent()`, `response()->make(status: …)`, `new Response(status: …)`, or `new JsonResponse(status: …)`, including a `->make()`/`->noContent()` reached through a same-class accessor — `$this->getResponseFactory()->make(status: …)` or `$this->responseFactory->make(status: …)` — whose declared return/property type is a Laravel `ResponseFactory`). The status comes from an explicit call-site argument, else the helper's `status` parameter default. The read is deliberately narrow: only a directly-returned body-less construction is trusted, so a response reached through a variable, a body-bearing one, a helper that delegates to another method, a vendor-declared helper, or a body-mutating chain all degrade to the bare success response with a note. (#549)
- API Resource responses are now inferred when the resource is wrapped in a `response()->json(<resource>, <status>)` call (e.g. `response()->json(UserResource::make($u), 201)` / `::collection(…)`): the return-expression reader unwraps the `json()` data argument and resolves it as any other resource shape. A shared `Support\MethodBody\ResponseJsonCall` matcher backs both this and Core's inline-JSON reader. A non-resource `json()` payload keeps today's behaviour; the response documents the resource under the conventional success status. (#517)
- `operation.response-type-abstract` lint rule (Underspecified): flags a 2xx response whose payload derives from an abstract or framework API-Resource base (`JsonResource`, `ResourceCollection`, `AnonymousResourceCollection`, `JsonApiResource`, or an app-defined abstract subclass), which resolves to an empty schema; the message names the concrete-subclass fix. It stays silent for concrete resources and resolved collections, and documents the `->toResource()` un-narrowable caveat. (#553)

### Changed
- `spatie/laravel-data` is now a soft dependency (moved from `require` to `require-dev`); Fractal and query-builder packages are opt-in.
- Widened dependency support: `zircote/swagger-php` `^5.8 || ^6.1.2` and `symfony/type-info` `^7.4 || ^8.0`; PHPDoc parsing now uses `phpstan/phpdoc-parser` + `symfony/type-info`.
- Auto-derived operation tags come from the controller's pluralised short class name; operation-ID derivation is selectable via `openapi.operation_id_strategy`.
- Pipeline order is expressed as a single ordered sequence in `BaselineRegistration::assemble()`; resolver fault isolation is centralized in `ResolverFaultBoundary`; pipeline classes are scoped singletons (Octane-safe).
- Restructured namespaces to separate the public extension surface (`Contracts\`) from internal infrastructure (`Support\`).
- `PaginatorKind` recognises Spatie's `PaginatedDataCollection`; `DataResponseResolver` handles union return types as `oneOf`.
- The inline `response()->noContent($status)` body-scan reads an explicit literal/named 2xx status (body-less); a non-literal or non-2xx status degrades. (#328)
- A typed `UploadedFile` property on a Spatie `Data` class (transitively, through nested Data classes) emits a `multipart/form-data` body with a `format: binary` field, matching the FormRequest file-rule path; the `multipart.file-without-multipart` lint rule is reframed as a contradiction guard that fires only when a `#[RequestBody]` override forces a non-multipart media type onto a file-carrying payload. (#333)
- The `migration.*` redundancy oracle (`SchemaEquivalence`) now follows a component `$ref` by name to its target schema on each side when the author and convention named the same component differently, so a parent schema whose only difference is a divergent child `$ref` name is no longer under-reported as non-redundant; resolution is conservative (an unresolvable ref keeps the annotation) and cycle-guarded. (#198)
- Lint `Rule` contract now declares `id`, `severity`, and `description` as readable property requirements instead of getter methods; rule implementations declare them as plain typed properties with initializers. (#379)
- Internal: unified the two docblock/type → schema engines on a single `symfony/type-info` `Type` representation (`TypeNodeToSchema` is removed; `JsonSchemaFromType` grew the structural array-shape/list/map cases and an optional leaf-class callback), with a `TypeNodeResolver::toType()` phpstan → symfony boundary. No spec output change except previously-unmapped array/collection shapes on the symfony path now resolve, `true`/`false` map to `boolean`, and array-shape properties serialize in sorted key order. (#480)
- Internal: the `migration.*` lint rules now compare authored annotations against a retained inference-only view of the single generation instead of running a second, harvester-excluded generation; the `SpecPipeline` is a plain executor again (no per-run stage exclusion), and an ordinary `openapi:generate` pays nothing for the retention. (#208, #483)
- Internal: the body-scan readers now resolve a call argument by name or position through a single shared `Support\MethodBody\CallArgumentResolver`, replacing four copies of the same logic. No spec output change. (#512)
- `PrimaryResponseResolver::resolvePrimaryResponse()` now returns a `Contracts\Registry\PrimaryResponse` instead of a bare `OA\Response`; build one with `PrimaryResponse::of($response)`, and pass `statusIsExplicit: true` when the status was read from the action itself. `null` still means "pass to the next resolver". This replaces the transient `x-laravel-openapi-explicit-status` vendor extension, which a bundled plugin had to smuggle past the contract by reaching into an `OperationBuilder` constant. No spec output change for the bundled resolvers, but it also fixes a latent bug: setting the marker overwrote a response's whole `x` array, so an out-of-tree resolver that set its own vendor extensions alongside an explicit status had them silently discarded. They are now preserved. (#516)
- Inferred `in: header` parameters now skip reserved / protocol header names (`Authorization`, `Content-Type`, `Content-Length`, the RFC 9110 negotiation / representation / conditional / control headers, `Host`, `Cookie`, `User-Agent`, …), matched case-insensitively, to cut protocol-header noise from `$request->header(...)` reads. Custom (`X-*`) headers are unaffected, and an explicit `#[Header]` is never filtered. (#530)

### Fixed
- Compatibility with `zircote/swagger-php` 6.4, which moved `OpenApi\Pipeline` to `OpenApi\Utils\Pipeline` and now hands the base class to `withProcessorPipeline()` callbacks. The SwaggerPhp harvester's callback no longer pins the old subclass in a parameter type, so the scan works across the whole supported range (5.8, 6.1 to 6.4).
- Lint now surfaces top-level and field-level bare `oneOf` / `anyOf` schemas across components, responses, and request bodies. (#294, #318)
- Edit-time PHPStan rules resolve positionally-written attribute arguments, not just named ones. (#322)
- `ErrorResponseInferenceStage` catches `Exception` only, so misbehaving resolvers throwing `Error`/`TypeError` fail loudly. (#308)
- `ResourceConventionResolver` gates on the pinned emitted verb on multi-verb routes. (#307)
- Generation no longer crashes on stale route definitions, closure middleware, FormRequests reading runtime state, malformed import-type docblocks, bare Rule objects, or non-instantiable controllers.
- Schema correctness fixes: untyped descriptors no longer default to `type: string` (#291); JSON list casts no longer typed as `object` (#249); `DateTimeInterface` maps to date-time strings (#148); array fields always emit `items`; path parameters always `required`; OpenAPI 3.1 nullable type arrays preserved on swagger-php 6; encrypted casts mapped like their plain counterparts; class-form object casts recognised (#252).
- `#[PublicEndpoint]` suppresses the middleware-derived 401/403 (#259); `#[IgnoreLint]` scoping fixed at class, payload, and schema level; query parameters deduplicated across resolvers; `operationId`s sanitised for codegen-safe identifiers (#42).
- `#[AllowedFilter(nullable: true)]` widens the generated `filter[…]` schema to a nullable type array.
- `--path` / `--diff` no longer leak findings for out-of-scope routes (#50).
